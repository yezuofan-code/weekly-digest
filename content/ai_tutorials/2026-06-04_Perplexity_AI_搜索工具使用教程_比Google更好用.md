# 我用 Perplexity 三个月，终于把 Google 从浏览器书签栏删了

你是不是也这样：每次搜东西，先得手动加个 `site:zhihu.com` 或 `site:reddit.com` 才能避开一堆 AI 生成的水文？搜个代码报错，翻两页都是复制粘贴的垃圾博客。更别提查资料时，得在 10 个标签页之间来回跳，最后还得自己总结——我就想知道一个答案，Google 却甩给我一堆链接让我自己挑。

我一个月前也这么痛苦，直到朋友硬塞给我 Perplexity AI。一开始我嗤之以鼻：“不就是套壳 ChatGPT 吗？”结果用了三天，真香了。现在它是我浏览器里打开最频繁的标签页，Google 退居二线，只在极少数情况下才切回去。

**先泼盆冷水：** Perplexity 不是万能的。它有时会编造来源（幻觉问题），免费版次数有限（每 4 小时 5 次 Pro 搜索），而且国内直连不太稳定，需要配合网络加速工具。但如果你愿意折腾一下，它能节省你至少 **30% 的搜索时间**。

我用它覆盖了三个高频场景：**写文章、写代码、学外语**。下面全是实操，你跟着走一遍就能上手。

## 1️⃣ 写作场景：从“找素材”直接跳到“初稿”

以前写一篇技术教程，流程是：Google 搜关键词 → 打开 5 个网页 → 对比信息 → 整理笔记 → 开始写。光“整理笔记”这一步就要花 20 分钟。现在我用 Perplexity 一步到位。

**怎么操作？**  
打开 [perplexity.ai](https://www.perplexity.ai)，不用注册也能用，但注册后能保留历史记录。我会在搜索框里输入这样一个“提示词”：

> 我是一位中文技术博主，想写一篇关于“Docker 容器日志管理”的入门教程，面向有 1 年 Linux 经验的开发者。请帮我：  
> 1. 列出最重要的 3 种日志查看命令（docker logs、tail、journalctl）的对比  
> 2. 给出每个命令的典型使用场景和坑点  
> 3. 提供一个实际排查日志的案例（比如容器日志爆满如何处理）  
> 4. 所有信息需要标注来源链接，避免幻觉

注意我加了 **“标注来源链接”**。Perplexity 默认会给出答案和引用（像学术论文那样带右上角数字），但如果你不主动要求，它可能漏掉。加上这句后，它会把每条信息对应的网页标出来，我可以点进去核实。

**效果：** 30 秒内，它给我一个结构清晰的回答，有对比表格、有案例、有 4 个来源。我直接复制到 Notion 里当大纲，再补充自己的经验细节，一篇文章的初稿就有了。

**和 Google 比好在哪里？**  
- Google 只给链接，我要自己阅读 5 个页面才能总结出这个表格  
- Perplexity 直接给了结构化信息，而且来源可查，不怕编造

**缺点：** 如果问题太冷门（比如某个小众 Open Source 项目的内部 API），Perplexity 的回答质量明显下降，甚至直接说“找不到相关信息”。这时我会切回 Google 搜 Stack Overflow 或 GitHub Issues。

## 2️⃣ 编程场景：报错排查 + 代码生成，但要警惕“幻觉代码”

程序员遇到报错，第一反应是复制粘贴到 Google。但 Google 的搜索结果里经常混着过时的解决方案（比如 Python 2 时代的代码）。Perplexity 因为能结合上下文和实时网络搜索，给出的解决方案通常更新、更直接。

**实操步骤：**  
假设我在写 Python 脚本时遇到 `ModuleNotFoundError: No module named 'pandas'`。我直接复制报错到 Perplexity 搜索框，然后加一句：

> 我是在 Windows 10 的虚拟环境（venv）下运行的，已经执行了 pip install pandas。帮我排查这个报错的原因，列出 3 种最常见的解决方法，并解释每种方法的适用场景。

它会返回：① 检查虚拟环境是否激活 ② pip 安装时是否指向了系统级 Python ③ 检查 requirements.txt 是否冲突。每个方法都附带了 Stack Overflow 或官方文档的链接。

**注意：** Perplexity 有时候会生成看起来合理但其实错误的代码。比如我问它“用 Python 写一个斐波那契数列的动态规划版本”，它给出的代码可能逻辑正确但性能不是最优的。**永远不要直接复制生产代码**，特别是涉及安全、密码或敏感操作时。

**最佳组合拳：**  
- 用 Perplexity 理解问题和获取思路  
- 用 GitHub Copilot 或 Claude 写具体实现  
- 用 Google 搜索特定 error code 的权威资料（比如微软官方文档）

我用了三个月，发现它在 **“解释技术概念”** 方面最强。比如不懂 CQRS 模式，直接问“用银行转账的例子解释 CQRS 模式”，它会给出业务场景 + 伪代码 + 优缺点，比看 10 篇博客都管用。

## 3️⃣ 翻译 & 外语学习：比 Deepl 更“懂”上下文

我英语阅读还行，但写邮件或翻译技术文档时，经常卡在“这个单词在技术语境下该怎么翻？” Deepl 可能直接按字面翻译，错的离谱。Perplexity 的优势在于它能理解上下文，甚至能按需求调整语气。

**翻译场景示例：**  
> 请将以下英文段落翻译成中文，保持技术文档的正式语气，并且将“child process”和“fork”这样的术语保留原词或使用行业内标准译法：  
> “When a process calls fork(), the operating system creates a new process called the child process. The child process is an exact copy of the parent process, except for the return value of fork().”

它翻译的结果是：“当一个进程调用 fork() 时，操作系统会创建一个新进程，称为子进程（child process）。子进程是父进程的精确副本，除了 fork() 的返回值不同。” 保留术语、语法正确、没有生硬感。

**外语学习场景：**  
我每天会用它做“角色扮演对话”。比如：

> 假设你是一个 native English speaker，正在和同事讨论一个技术方案的利弊。我会用中文表达我的观点，请你先用自然的美式英语重写我的句子，然后解释为什么这样写更地道。开始我的句子：“我觉得用微服务太复杂了，不如单体应用简单。”

它会回复：英文重写版 “I think microservices add too much complexity; a monolithic approach might be simpler for now.” 然后解释：原句“太复杂了”变成“add too much complexity”更客观；“不如…简单”用“might be simpler”语气更缓和，适合职场讨论。

**缺点：** 免费版每次搜索只能搭配一个默认模型（默认是 GPT-4 或 Claude 3，取决于你设置），无法像 ChatGPT 那样保留长对话历史。如果你需要连续追问 5 轮以上，建议用 Pro 版或者单独开一个新 Thread。

## 4️⃣ 彩蛋：Perplexity Pro 值得买吗？我的真实账本

我用的是 Pro 版（$20/月），但我不建议你上来就付钱。先免费试用 1 个月（官方有试用期，或者用邀请链接）。

| 功能 | 免费版 | Pro 版 ($20/月) |
|------|--------|-----------------|
| Pro 搜索次数 | 每 4 小时 5 次 | 无限次 |
| 选择 AI 模型 | 仅默认 | 可切换 GPT-4、Claude 3 Opus、Gemini |
| 文件上传 | ❌ | ✅ (上传 PDF/图片进行分析) |
| 搜索质量 | 日常够用 | 复杂推理时明显更准 |
| 是否必须付费 | 不必须 | 重度使用者推荐 |

**我为什么付了钱：**  
- 每天写代码查资料超过 30 次，免费版每次用完 5 次就要等 4 小时，太焦虑  
- 上传 PDF 功能帮我快速读论文，省了我很多时间  
- Claude 3 Opus 模式下回答逻辑更严密，适合技术深度分析  

**劝退场景：**  
如果你只是偶尔搜搜菜谱、查查天气预报，免费版完全够用。甚至你还可以搭配 Bing Chat（Copilot），也是免费的，效果类似。别为了“AI 搜索”盲目付费。

## 最后提醒几句 ⚠️

1. **网络问题：** Perplexity 在国内无法直连，需要全程开启网络加速工具。推荐用一些稳定且速度快的外网访问工具（我不具体推荐，你自己选）。  
2. **不要迷信引用：** 虽然它标了来源，但有时引用的网页内容本身就过时或错误。**重要信息请点进来源核实**。  
3. **隐私注意：** 免费版会上传你的查询内容到云端训练模型（官方说明里提到）。如果你搜的是公司保密代码或私人信息，建议用本地模型（比如 LLaMA）或仅用 Pro 版并关闭数据训练选项。  
4. **先免费试用：** 别冲动订阅 Pro，先用一个月免费版，看自己每天是否能用到 5 次以上。很多人一周后就习惯了免费版。
